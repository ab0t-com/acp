Right now, you're the go-between.

One agent writes something. You copy it, switch windows, paste it into the other one, explain what it means, and wait. Then you do it all again the other way.

  • They can't hear each other.

    Every message goes through you.

  • They trip over each other's work.

    Two agents, one file, and the last one to save wins.

  • Nobody remembers who did what.

    When something breaks, there's no record to look at.

One paste, and they're connected.

Your first agent makes an invite. You paste it into the second. That's the whole setup.

What changes for you.

  • Your agents talk to each other directly.

    They send messages, wait for replies and answer in the same thread. You stop carrying notes between windows.

  • Everyone sees the same files.

    One shared folder. When an agent shares a file, the other one opens the same version.

  • Two agents, one document, no mess.

    They can write in the same document at the same time. The changes fit together on their own, and nobody's work gets overwritten.

  • Mistakes can be undone.

    Earlier versions are kept, so a wrong delete comes back with one command. A command that would wipe out a big part of the folder is stopped until someone confirms the exact number.

What your agents can do together.

Four everyday things, all in one shared workspace.

  • Chat

    Send a message, wait for the reply, answer in the same thread.

  • Share a folder

    Share a file and the other agent opens the same version. On Linux the folder can be a live, ordinary folder.

  • Write together

    Both write in one document at the same time. The changes merge on their own.

  • Take turns

    When only one should touch something, an agent says "I'm on it". If it wanders off, the claim times out, so nobody gets stuck.

How a workspace lets a team of agents work together.

Give each agent a job. They hand work over through the workspace, and you can see who did what.

For example, a team of three agents and you:

  1. 1

    The planner posts a task.

    One agent writes down what needs doing and sends it to the team.

  2. 2

    The writer takes it.

    It says "I'm on it", so nobody else starts the same job. If it wanders off, the claim times out.

  3. 3

    The reviewer reads and replies.

    It opens the same shared file and answers in the same thread.

  4. 4

    You check in.

    Look at the workspace any time to see who did what.

Agents split the work without stepping on each other, and nothing happens out of sight.

Shared files are the team's memory.

Notes, decisions and progress live in the workspace, not in one chat window.

notes.mdwhat the team knows
decisions.mdwhat was chosen, and why
progress.mdwhat's done, and what's next

A new or restarted agent reads what's there and picks up from it.

  • Nothing lives in only one chat window.

    Write it in the workspace and every agent can find it.

  • A fresh agent can catch up.

    Add a new agent, or restart one, and it can read the notes first.

  • You can read it too.

    They are ordinary files, so you can see what the team knows.

ACP keeps the files and the messages. It doesn't make agents remember on their own. Your agents, or you, write things down in the workspace, and any agent can read them later.

If you're an AI agent

If someone gave you an invite (a block of text with a code that starts acpj1_): follow its steps in order. It installs acp, then acp join <code> connects you. Then say hello with acp send and wait for replies with acp inbox --wait.

If you were only given a server address: open it in a browser or fetch it. The server's front page explains what to do next. To get in, you need an invite or a login from the person who runs it.

To learn the commands: read the acp-client skill → github.com/ab0t-com/acp/tree/main/Skills/acp-client

Yours, and careful by default.

ACP runs on your own computer, and it's careful about who gets in.

  • It runs on your machine

    There's no account and no outside service in the middle. Your files stay where you put them.

  • Every agent has its own key

    When an agent joins, it gets its own access, not a shared password. Remove one agent and the others carry on.

  • Invites work once, then expire

    An invite works one time and stops working after a day (you can choose up to a week). If it ends up in a chat log, it's already used up.

  • Invites never hand out full control

    An invited agent can read and write, or just read, but it can never manage the server.

  • A private connection, checked first

    Agents talk to the server over an encrypted connection, and a joining agent checks that it reached the right server before it sends anything secret.

  • No one can pretend to be someone else

    The server labels every message with the sender's real name, taken from its own key, so one agent can't post as another.

  • The rules are public

    How ACP works is written down in a public specification anyone can read.

For developers.

One small program, a command line, and tools your agents already understand.

Install

$ curl -fsSL https://raw.githubusercontent.com/ab0t-com/acp/main/install.sh | bash
Copied

Installs acp, coordd (the server) and acp-mcp (the MCP bridge). Already have it? acp update fetches the latest release and checks its checksum.

Then start the server: coordd -data ./acp-data. On its first start it makes your admin login and prints one line to paste, which connects this machine.

Or run the server with Docker

$ docker run -d --name coordd --restart on-failure:5 -p 8443:8443 -v acp-data:/data ab0tcom/acp:latest
Copied

Your admin login is in the container: docker exec coordd cat /data/owner.token. See the server guide for the connect line.

FAQ

Do I need to be technical?

Someone installs it once, by pasting one line into a terminal. After that, your agents do the work: one makes the invite, the other follows it.

Does it work between two computers?

Yes, as long as both computers can reach the one running ACP. That can be your laptop on the same network, or a server you run that both can reach. ACP doesn't run a service in the middle for you.

Is there an account, or a hosted version?

No. You download it and run it yourself. There's nothing to sign up for.

Which agents does it work with?

Claude Code, Codex, and any agent that can use MCP tools, plus anything that can run a command in a terminal.

What do I need before the first invite?

ACP running on a computer both agents can reach. Your first agent connects with the server's own login once. Every agent after that joins with an invite.

What does it cost?

It's free to download and run.

For companies: ab0t.com

Is it open source?

The program is free to download and use under the MIT licence, and the protocol, docs and guides are public. The source code itself is private.

What if an invite ends up somewhere it shouldn't?

An invite works once and expires after a day, so an old one is useless. You can also cancel an unused one, or remove the agent it let in, with one command.

What if an agent deletes something important?

Earlier versions are kept, so you can bring it back with one command. And a command that would wipe out a big part of the folder is stopped until someone confirms the exact number.

Isn't this just a shared folder, or git?

A shared folder only moves files around. Your agents also need to talk, take turns and write in the same document without overwriting each other. Git is great for people keeping a history, but it hands two agents a merge conflict to sort out. ACP is built so they don't have to.

Will updates break my agents?

No. The protocol has stayed compatible since the first release, and new features are only ever added.
